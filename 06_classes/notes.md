# 第6章 学習メモ

## 理解できたこと
- class 定義と __init__ だけでインスタンスを生成し、self を使って固有状態とメソッドを持たせられる。
- インスタンス変数は goal や assist といったメソッドで更新でき、hasattr / getattr / setattr で状態を安全に扱える。
- クラス変数は全体共有の team_name や player_count を表し、@classmethod で cls を使って集計やファクトリを実装できる。
- 継承で Goalkeeper や Striker を Player から派生させ、super を使えば親の初期化や振る舞いを再利用しつつポリモーフィズムが得られる。
- Team クラスをモジュール化して __name__ == "__main__" ブロックで直接実行とインポート処理を分けられる。
- __len__ や __str__ を定義すれば len(team) や print(team) を自然に使える。

## 詰まったこと・疑問
- クラス変数とインスタンス変数を分ける基準が曖昧で、副作用を避ける運用ルールを決めたい。
- クラスメソッドと静的メソッドの使い分けで、状態への依存度をどう見極めるか悩みが残る。

## 気づき・応用アイデア
- Player と Team を別モジュールにして import しやすくすれば、メンテ性と再利用性が同時に上がる。
- from_string などのファクトリを使えば文字列や JSON からインスタンスを生成する処理を整理できる。
- 共通インターフェース introduce を使えば継承した異なる選手も同じループで扱えるので GUI/CLI 表示が簡単になる。
